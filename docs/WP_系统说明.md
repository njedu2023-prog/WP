# WP 系统说明

WP 只服务一个目标：

> 在 T 日 14:20-15:00 的可成交窗口内，于 14:55 前形成至多一笔买入决策，并提高按固定 T+1 收盘卖出后获得正净收益的概率。

系统不以“每天必须有票”为目标。没有足够证据时，`NO_TRADE` 是正式且正确的决策。

## 正式交易契约

- 观察窗口：14:20-14:44，只收集因果快照。
- 决策窗口：14:45-14:54，全部门槛通过才可锁定 `BUY`。
- 安全截止：14:55，仍未锁定 `BUY` 时正式记录 `NO_TRADE`。
- 收盘后：15:00 起禁止生成或修改可买名单。
- 入场价：正式信号锁定时的 `signal_price`。
- 退出价：下一 A 股交易日收盘价。
- 收益：先计算毛收益，再扣除配置中的往返交易成本。
- 每个交易日最多一条不可变正式记录，后续刷新不得替换代码、时间或价格。

## 运行链路

1. `Run WP Tail Session` 在 14:16 左右启动一个持续 runner。
2. 同一 runner 每 5 分钟覆盖 14:20 至 15:00，避免每个时间槽冷启动。
3. WP 优先使用 `direct_tushare` 构建当前市场输入；上游仓库只作归档和回退，不阻塞正式运行。
4. 旧规则分和 Top50 只生成研究候选池，不直接授权交易。
5. 概率层只使用早于当前交易日、能够证明来自合法尾盘时点的真实验证样本。
6. 决策层依次检查市场状态、数据新鲜度、独立样本日、有效样本量、成本后盈利概率、单侧置信下界、期望净收益、下行风险和候选稳定性。
7. 通过全部检查后才写入 `wp_strategy_ledger`；否则继续观察或记录 `NO_TRADE`。
8. T+1 收盘后用正式真值更新账本，Pages 只展示正式策略净收益。

## 输出边界

- `outputs/json/wp_decision_support.json`：当日唯一正式决策。
- `outputs/json/wp_strategy_ledger.json`：不可变正式策略账本。
- `outputs/json/wp_t1_forecast.json`：候选的成本后概率与风险估计。
- `outputs/json/wp_legacy_history_audit.json`：旧历史快照完整性审计。
- `outputs/csv/wp_buy_plan_validation.csv`：研究样本账本，不等于正式策略绩效。
- `outputs/backtests/**`：收盘日线代理研究，不授权实盘交易。

## 历史数据原则

盘后生成的名单不能回填成盘中可交易信号。2026-07-21 至 2026-07-24 的旧记录按快照时间审计：

- 07-21 有合法盘中快照，但旧版正式意见为空仓，只保留为研究历史。
- 07-22、07-23、07-24 没有 14:20-14:54 的有效快照，统一标记为缺失并按未交易处理。

任何收益统计都不得使用 15:00 后才出现的候选名单。

## 可靠性

- GitHub Actions cron 是尽力调度，因此主流程使用单个常驻尾盘会话和稀疏自愈监控。
- Pages 使用 `main` 分支自动构建，避免两套部署机制重复发布。
- 工作流使用并发锁保护输出写入。
- 交易日以 A 股交易日历为准，不按自然日推导 T+1。
- 系统只提供人工决策支持，不连接券商，不自动下单。
