# WP V6 运行手册

## 工作流边界

### Run WP V6 Tail Session

- 北京时间 13:40 启动，为 GitHub 定时任务可能的排队延迟预留余量；
- 14:00、14:05、14:10、14:15 只采集暖机 5 分钟 K 线，不运行候选判定；
- 按绝对时钟锚定 14:20、14:25、14:30、14:35、14:40、14:45、14:50，
  每个时点延后 2 分钟读取已完成的精确 5 分钟 K 线；
- 一个 warm runner 覆盖全部时点，避免多个冷启动任务竞争；
- 单槽异常不会阻断后续冻结和清场，但工作流最终标记失败并保留槽位证据；
- 每个信号槽先结算上一槽首次出现候选的参考成交价；
- 14:55 专门结算 14:50 候选，然后冻结候选台账；
- 15:00 页面 `buy_plan_count` 必须为 0。
- 14:52 只接受时间戳严格等于 14:50 的已完成 K 线；任何 14:50 之后的
  行情不得回填或改写 14:50 候选。

### Validate WP Close

- 北京时间 15:08 启动，最多轮询至 16:10；
- 只处理 `target_trade_date <= today` 的待验证候选；
- 日线、涨跌停和复权真值均超过 1,000 行才接受；
- 真值未到时保留 pending，不伪造、不提前完成。

### Research WP V6 Full Three-Year OOS Model

- 手动或每月非交易时段运行；
- 构建约五年因果面板，最后连续三年才计入正式样本外成绩；
- 历史接口响应和因果面板使用 Actions cache，扩展区间时只补取缺失前缀；
- 每次研究先生成绑定本次日期区间的 `wp_v6_resolved_config.yml`，分片和汇总
  必须使用同一份配置；
- 模型文件按模型指纹保存并绑定训练数据摘要，不能覆盖；
- 任何月度重训得到的新模型均先进入 `RESEARCH`，不得替换正在积累证据的
  影子模型；
- 150 日影子统计只接受精确匹配 `model_fingerprint` 的未来实时会话，禁止
  跨模型累计，也禁止历史回放计数。

## 故障不变量

- 没有模型：显示 `MODEL_NOT_READY`，候选数为 0。
- 模型未晋级：只显示 `SHADOW_QUALIFIED`，不生成正式买入计划。
- 数据超过 420 秒：所有股票 `passes_freshness=false`。
- 少于 5 根连续盘中快照：该股票不可进入候选。
- 单票分时延迟超过 5 分钟或全市场覆盖不足 90%：失败关闭，不生成候选。
- 同一槽重复运行：候选台账不增加重复出现次数。
- 入场结算缺失：不得回退首次信号价；冻结状态为 `INCOMPLETE_ENTRY`。
- 14:50 后：禁止使用新抓取的数据新增候选；合法 14:50 快照可在冻结前完成。
- 15:00 后：页面不展示可买名单。
- T+1 真值缺失：保持 pending。
- 跌停收盘或停牌：按退出失败处理；缺价采用固定 -10% 惩罚。
- 复权因子缺失：保持 pending，不允许原始价格回退。
