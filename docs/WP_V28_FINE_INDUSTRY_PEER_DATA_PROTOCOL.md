# WP V28 细分行业同频三年数据协议

## 1. 研究问题

V24/V25 已证明：仅依靠候选自身与同槽候选之间的排序，不能稳定区分 T+1
净收益。V28 不重新选择股票，而是验证一个独立机制：

> 一支尾盘候选的上涨如果得到当时细分行业多数股票同步确认，是否比孤立冲高
> 更可能在固定 T+1 收盘退出后取得正净收益？

本阶段只构建结果盲特征，不读取、连接或统计任何 T+1 收益。

## 2. 不可变来源

- 全市场 5 分钟数据：
  V9 run `30600193544` 的缓存
  `wp-v19-panel-20210726-20260724-20230727-20260724-r15-30600193544`；
- 候选身份：
  V24 data run `30635569735` 的
  `wp_v24_outcome_blind_candidate_index.parquet`；
- 候选集合固定为 V24 每槽最多 5 支，不在 V28 数据构建中重排、扩充或删除；
- 行业归属只使用 Tushare `index_member_all` 的历史生效区间；
- 前收盘价只使用当日 `daily.pre_close`；
- 分钟字段只读取
  `ts_code,trade_date,trade_time,close,amount`。

源文件和每个月分钟分区必须通过 manifest SHA-256 校验。

## 3. 时间与样本

- 固定信号槽：
  `14:20,14:25,14:30,14:35,14:40,14:45,14:50`；
- 只处理不可变 V24 候选索引中的交易日；
- 20 分钟动量使用精确的
  `14:00-14:30` 等历史 5 分钟槽，不允许向后取最近值；
- 行业 `in_date` 当日生效，`out_date` 当日失效；
- 每个日期、槽位、股票只能有一条身份记录。

## 4. Leave-One-Out 不变量

计算某候选的 L2 或 L3 行业特征前，必须先从同行集合剔除该候选自身。
候选本身不得提高行业宽度、中位数、成交强度或任何确认指标。

每个 L2/L3 层级固定构建：

- 同行数量与有效收益数量；
- 当日涨幅的中位数、均值、75% 分位、四分位距、标准差和最大值；
- 同行上涨比例，以及涨幅超过 2%、5%、7% 的比例；
- 同行最近 20 分钟涨幅中位数、75% 分位和上涨比例；
- 候选相对同行中位数、75% 分位和最大值的差；
- 候选在同行中的当日涨幅百分位；
- 候选 5 分钟成交额相对同行中位成交额的对数差。

任何字段不得使用未来价格、T+1 结果或事后人工选择。

## 5. 全量覆盖门槛

完整三年结果盲构建必须同时满足：

- 未解决查询失败为 0；
- 候选身份与 V24 索引 100% 一致，且无重复；
- 时间戳日期一致率 100%；
- 至少 98% 的候选交易日通过逐日门槛；
- 至少 98% 的日期槽位通过逐槽门槛；
- 至少 98% 的候选拥有完整 L2/L3 特征；
- 每个完整候选至少有 4 个 L2 同行、2 个 L3 同行。

逐槽门槛沿用已通过的 V28 探针协议：

- 至少 1,000 支股票；
- 前收盘价覆盖不低于 98%；
- L2、L3、当日收益和 20 分钟收益覆盖均不低于 95%；
- 至少 80 个含 5 支以上股票的 L2 行业；
- 至少 120 个含 3 支以上股票的 L3 行业。

## 6. 授权边界

只有全部数据门槛通过，才允许在另一个提交中预注册 V28 模型、训练窗口、
嵌套样本外切分、发布频率和盈利验收门槛。

数据构建通过不代表模型盈利，不授权影子运行，更不授权生产使用。模型协议必须
在首次连接 T+1 收益之前固化。
