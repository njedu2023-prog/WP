# WP V27 THS 历史热榜 Schema 归一化可行性协议

## 1. 目的

V26 证明 THS 在 2023 年已有盘中热榜批次，但 2023-08 的 `rank` 字段不是
后续年份使用的 1-100 序号。V27 只验证：

> 能否完全依靠同一历史快照中的字段，把旧 schema 客观归一化为可比较的
> 1-N 排名，并支持正式三年样本期的全量覆盖审计？

本阶段不读取任何 T+1 收益、胜负标签或候选结果。

## 2. 固定数据源

- 只使用 Tushare `ths_hot`；
- `market=热股`；
- `is_new=N`；
- 使用字段：
  `trade_date,data_type,ts_code,ts_name,rank,pct_change,current_price,concept,hot,rank_time`；
- 只使用 `rank_time <= 14:50` 的历史批次。

DC 因 2023 至 2024 年初无数据被排除。`sw_mins` 因当前账户无权限被排除。

## 3. 固定探针日期

- 2023-07-28
- 2023-08-25
- 2023-09-28
- 2023-10-31
- 2023-11-30
- 2023-12-29
- 2024-03-15
- 2024-09-27
- 2025-01-15
- 2025-07-23
- 2026-01-15
- 2026-07-23

不得替换无数据或 schema 异常的日期。

## 4. 固定批次选择

1. 将原始 `rank_time` 解析为交易所本地时间；
2. 只保留 13:20-14:50；
3. 选择最后一个分钟桶；
4. 若同一分钟有多个完整抓取，按精确 `rank_time` 分组，选择最后一个
   不少于 50 支且代码不重复的批次；
5. 禁止把多个抓取批次合并。

## 5. 固定 Schema 归一化

### 现代序号模式

若 `rank`：

- 至少 95% 可解析；
- 起点为 0 或 1；
- 最大值不超过 2,000；
- 至少 95% 唯一；

则直接平移为从 1 开始的序号。

### 历史热度分数模式

只有同时满足以下条件才允许归一化：

- `rank` 全为正值且至少 95% 唯一；
- `rank` 的最小值大于 2,000，明确不是序号；
- 同批次 `hot` 至少 95% 可解析；
- `rank` 与 `hot` 的 Spearman 相关系数不低于 `0.99`；
- `hot` 越大代表热度越高，固定按降序生成 1-N 序号；
- 归一化后至少 95% 排名唯一。

如果旧 `rank` 无法由同批次 `hot` 验证，禁止使用返回行顺序、股票涨幅或未来收益
推断排名。

## 6. 通过门槛

十二个探针日期必须全部满足：

- 有 13:20-14:50 完整批次；
- 至少 50 个唯一 A 股代码；
- 代码无重复；
- `trade_date` 与 `rank_time` 日期一致；
- 现代序号模式或经验证的历史热度分数模式二者之一成立；
- 归一化排名有效；
- 不读取任何收益字段。

全部通过才允许进入 2023-07-27 至 2026-07-24 的全交易日覆盖构建。

## 7. 下一道门槛

全量构建仍必须满足：

- 交易日覆盖率不低于 98%；
- 14:20-14:50 七个信号槽覆盖率不低于 98%；
- 时间戳因果有效率 100%；
- schema 归一化成功率不低于 98%；
- 不读取任何 T+1 结果。

探针通过不代表模型盈利，也不授权影子或生产运行。
