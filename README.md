# WP V41 - 14:00 T+1 决策支持系统

WP 只解决一个可验证问题：

> 在 A 股交易日 14:00，找出按固定执行合同买入、并在下一交易日收盘卖出后，
> 最可能取得正净收益的主板股票。

系统只发布模型结果，不连接券商、不自动下单，也不记录用户是否买入。人工拥有
全部交易决定权。合格票可以为 0，系统不得为了凑名单降低门槛。

## 当日输出

14:00 形成两个严格分离的队列：

| 队列 | 数量 | 含义 | 是否用于正式策略统计 |
| --- | ---: | --- | --- |
| 合格候选 | 0 至多支 | 通过全部固定门槛，供人工决策 | 是 |
| 观察 | 固定 5 支 | 可成交但未通过全部门槛的最近邻样本 | 否，单独研究统计 |

观察票不是“次优推荐”。它用于持续检验当前门槛是否有区分价值。若真实可用
股票不足 5 支，系统报告数据或股票池完整性故障，不补造股票。

## 固定交易合同

| 项目 | V41 合同 |
| --- | --- |
| 因果暖机 | T 日 13:30–13:55，每 5 分钟采集一次，只形成当时可见特征 |
| 决策时点 | T 日 14:00，仅一次 |
| 股票范围 | A 股主板，排除 ST、停牌、上市不足 60 日及不满足流动性约束的股票 |
| 参考订单 | 100,000 元，且不超过 14:05 五分钟成交额的 1% |
| 可见信号价 | 14:00 已完成五分钟线收盘价 |
| 影子入场价 | 14:05 已完成五分钟线收盘价加 10bp 滑点 |
| 费用及退出影响 | 25bp |
| 基准全成本 | 35bp |
| 压力全成本 | 50bp |
| 退出 | T+1 14:57 提交跌停价限价单参加收盘集合竞价，以收盘撮合价结算 |
| 入场未成交 | 现金收益 0，正收益标签记失败 |
| 已入场但无法退出 | 固定记 `-10.00%` 惩罚，不删除样本 |
| 页面截止 | 14:10 冻结台账；15:00 后清空可买展示 |

合格和观察都锁定相同的 14:00 信号、14:05 入场基准、模型指纹和策略指纹。
后续刷新、盘后价格或人工选择均不能改写。

完整定义见 [V41 策略合同](docs/STRATEGY_CONTRACT.md)。

## 模型结构

V41 复用已验证的因果数据和训练基础设施，但不继承任何旧时点收益结论：

1. **因果基础评分器**：学习入场成交、T+1 退出、成交后正收益、严重亏损、
   条件收益和横截面相对强度。
2. **元模型**：只使用严格样本外的基础模型预测与当时可见状态，估计正净收益
   概率、期望净收益和严重亏损概率。
3. **退出风险层**：独立估计 T+1 无法顺利退出的风险。
4. **V41 固定政策**：只在 14:00 应用冻结的概率、收益、风险、成交率和排名
   门槛，同时输出全部合格票和 5 支独立观察票。

V15/V40 的历史表现不能冒充 V41 表现。决策时点从 14:30 改为 14:00 后，
特征、价格、候选和真值都必须按新合同重新计算。

模型细节见 [V41 模型卡](docs/WP_V41_MODEL_CARD.md)。

## 证据边界

### 历史回测

- 展示区间：`2026-05-01` 至 `2026-07-31`。
- 每个外层测试折只能使用测试日之前的数据训练和校准。
- 选择过程不得读取 T+1 真值。
- 回测必须使用 14:00 信号和 14:05 入场，不能复用 14:30/14:35 的候选或收益。

### 真实影子统计

- V41 起始交易日：`2026-08-05`。
- 只统计已冻结 V41 模型在真实 14:00 产生并绑定精确模型指纹的记录。
- 历史回测、合格、观察和旧合同四套统计永不混合。
- 任意重训、门槛变化或合同变化都产生新指纹，150 日影子时钟从 0 重新开始。

历史门槛通过也只允许进入影子阶段。生产晋级至少需要 150 个未来交易日、
50 个候选日、250 支已验证合格候选，并同时满足收益、胜率、置信下界、
成交率、校准和 50bp 压力测试门槛。

验证方法见 [V41 回测与影子协议](docs/WP_V41_BACKTEST_PROTOCOL.md)。

## 自动化

1. `Build WP V41 Fixed 14:00 System`
   构建因果面板、严格滚动样本外模型、2026 年 5–7 月回测、冻结模型包和页面。
2. `Run WP V41 Fixed 14:00 Session`
   13:10 左右启动单个持续任务；13:30–13:55 暖机，14:00 决策，
   14:05 锁定入场基准，14:10 冻结，15:00 清场。
3. `Validate WP Close`
   收盘后轮询 T+1 真值，分别结算合格、观察和尚未封账的历史回测。
4. `Monitor WP System`
   只检查关键生命周期时点，不重复启动正常运行中的会话。

上游 `a-share-top3-data` 只用于真值归档，不阻塞 WP 的 direct Tushare 实时链路。
