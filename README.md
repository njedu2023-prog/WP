# WP V40 - 14:30 尾盘 T+1 决策支持系统

WP 只解决一个可验证问题：

> 在 A 股交易日 14:30，找出按固定执行合同买入、并在下一交易日收盘卖出后，
> 最可能取得正净收益的主板股票。

系统只发布模型结果，不连接券商、不自动下单，也不记录用户是否买入。人工拥有
全部交易决定权。合格票可以为 0，系统不得为了凑名单降低门槛。

## 当日输出

14:30 形成两个严格分离的队列：

| 队列 | 数量 | 含义 | 是否用于正式策略统计 |
| --- | ---: | --- | --- |
| 合格候选 | 0 至多支 | 通过全部固定门槛，供人工决策 | 是 |
| 标准观察 | 固定 5 支 | 可成交但未通过全部门槛的最近邻样本 | 否，单独研究统计 |

标准观察不是“次优推荐”。它的作用是持续回答：当前门槛排除的股票，真实结果
是否比合格候选更差。若真实可用股票不足 5 支，系统报告数据或股票池完整性故障，
不会补造股票。

## 固定交易合同

| 项目 | V40 合同 |
| --- | --- |
| 决策时点 | T 日 14:30 |
| 股票范围 | A 股主板，排除 ST、停牌、上市不足 60 日及不满足流动性约束的股票 |
| 参考订单 | 100,000 元，且不超过 14:35 五分钟成交额的 1% |
| 可见信号价 | 14:30 已完成五分钟线的收盘价 |
| 影子入场价 | 14:35 已完成五分钟线收盘价加 10bp 滑点 |
| 费用及退出影响 | 25bp |
| 基准全成本 | 35bp |
| 压力全成本 | 50bp |
| 退出 | T+1 14:57 提交跌停价限价单参加收盘集合竞价，以收盘撮合价结算 |
| 入场未成交 | 现金收益 0，正收益标签记失败 |
| 已入场但无法退出 | 固定记 `-10.00%` 惩罚，不删除样本 |
| 页面截止 | 14:40 冻结台账；15:00 后清空可买展示 |

合格候选和标准观察都锁定相同的 14:30 信号、14:35 入场基准、模型指纹和
策略指纹。后续刷新、盘后价格或人工选择均不能改写。

完整定义见 [V40 策略合同](docs/STRATEGY_CONTRACT.md)。

## 模型结构

V40 复用已验证有信息价值的基础设施，不继承旧版本收益结论：

1. **V9 因果基础评分器**：学习入场成交、T+1 退出、成交后正收益、严重亏损、
   条件收益和横截面相对强度。
2. **V10 元模型**：只使用严格样本外的基础模型预测与当时可见状态，估计正净
   收益概率、期望净收益和严重亏损概率。
3. **V14/V15 退出风险层**：独立估计 T+1 无法顺利退出的风险。
4. **V40 固定政策**：只在 14:30 应用 V15 研究中冻结的概率、收益、风险、
   成交率和排名门槛；取消旧版跨时点和每日 Top 3 规则。

V15 的历史表现不能冒充 V40 表现。固定 14:30、全部合格票和独立观察队列是
新的决策合同，必须重新回测并重新开始未来影子统计。

模型细节见 [V40 模型卡](docs/WP_V40_MODEL_CARD.md)。

## 证据边界

### 历史回测

- 请求区间：`2026-05-01` 至 `2026-07-31`。
- 实际首个交易日：`2026-05-06`。
- 每个外层测试折只能使用测试日之前的数据训练和校准。
- 选择过程不得读取 T+1 真值。
- 2026-07-31 的 T+1 是 2026-08-03；该日收盘真值到位前，三个月报告必须
  显示 `INCOMPLETE`，不能宣称盈利。

### 真实影子统计

- 精确起始交易日：`2026-08-03`。
- 只统计由已冻结 V40 模型在真实 14:30 产生并绑定其精确模型指纹的记录。
- 历史回测、合格候选、标准观察三套统计永不混合。
- 任意重训、门槛变化或合同变化都产生新指纹，150 日影子时钟从 0 重新开始。

历史门槛通过也只允许进入影子阶段。生产晋级至少需要 150 个未来交易日、
50 个候选日、250 支已验证合格候选，并同时满足收益、胜率、置信下界、
成交率、校准和 50bp 压力测试门槛。

验证方法见 [V40 回测与影子协议](docs/WP_V40_BACKTEST_PROTOCOL.md)。

## 自动化

1. `Build WP V40 Fixed 14:30 System`
   构建因果面板、严格滚动样本外模型、2026 年 5–7 月回测、冻结模型包和页面。
2. `Run WP V40 Fixed 14:30 Session`
   13:40 启动单个持续任务；14:00–14:25 暖机，14:30 决策，14:35 锁定
   入场基准，14:40 冻结，15:00 清场。
3. `Validate WP Close`
   收盘后轮询 T+1 真值，分别结算合格候选、标准观察和尚未封账的历史回测。
4. `Monitor WP System`
   只检查关键生命周期时点，不重复启动正常运行中的尾盘会话。

上游 `a-share-top3-data` 只用于真值归档，不阻塞 WP 的 direct Tushare 实时链路。
