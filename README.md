# WP V9 - 尾盘 T+1 正净收益候选系统

WP 只优化一个可检验目标：

> 最大化 A 股主板股票在 T 日 14:20-14:50 可成交买入后，按固定 T+1
> 收盘卖出并扣除既定往返成本后，净收益大于 0 的概率。

系统发布全部通过固定门槛的候选，由人工决定是否买入以及买哪一支。零候选是
正常结果，模型不得为了生成名单放宽门槛。

## 设计原则

- 标签就是固定交易合同的 `net_return_pct > 0`，不是涨停、排名或未来最高价。
- 历史训练和实时推理共享同一套 5 分钟因果特征代码。
- 主模型分别学习买入成交、T+1 可退出和完成往返后的条件收益，再按真实执行
  路径合成全路径净盈利概率与期望收益。
- 直接全路径模型只保留为审计，不参与候选排序或授权。
- 候选由因子化净盈利概率、期望收益、条件收益排序、严重亏损风险和模型稳定性
  共同决定，成交概率作为硬门槛。
- 概率校准期与政策证据期按时间前后分开，测试集不参与门槛或模型选择。
- 每支股票第一次通过即锁定信号时间、信号价、模型和政策指纹；下一根
  5 分钟线独立锁定参考成交价。
- 所有 14:20-14:50 出现过的候选逐票验证；模型候选不等于用户实际成交。
- 三年滚动样本外回测通过后，仍必须完成至少 150 个未来交易日的影子运行。

## 固定交易合同

| 项目 | 合同 |
| --- | --- |
| 信号时点 | 14:20、14:25、14:30、14:35、14:40、14:45、14:50 |
| 股票范围 | A 股主板 |
| 参考订单 | 100,000 元，且不超过当前 5 分钟成交额的 1% |
| 入场价 | 信号后下一根 5 分钟线收盘价加 10bp 滑点 |
| 费用及退出影响 | 25bp |
| 基准全成本 | 35bp |
| 压力全成本 | 50bp |
| 退出 | 下一 A 股交易日 14:57 提交跌停价限价卖单参加收盘集合竞价，按收盘撮合价结算 |
| 未成交 | 买入未成交记现金收益 0；已买入但 T+1 无法退出采用预先声明的 -10% 惩罚 |
| 截止 | 14:50 后禁止新增，14:55 冻结，15:00 清除可买展示 |

完整定义见 [STRATEGY_CONTRACT.md](docs/STRATEGY_CONTRACT.md)。

## 模型

252 日和 504 日两个时间尺度分别训练入场成交、条件退出、完成往返后的正收益
与严重亏损、条件收益均值与 10% 分位、条件横截面领先和 LambdaRank。主概率
固定为三段概率乘积；主期望收益显式计入退出失败惩罚。直接全路径模型只用于
独立审计。所有概率均使用严格早于测试期的 42 日窗口校准。

最终选择分综合因子化期望收益、条件期望收益、条件正收益概率、条件收益排序和
严重亏损安全分位。资格门槛只允许由当前测试折之前的 84 日样本外设计期搜索。
设计期先选出唯一冠军政策，随后 42 日样本外确认期只检验这一个政策一次；任一
证据不足则该折输出 `NO_SIGNAL`，不得在确认期轮试其他政策。

特征覆盖：

- 14:00 至当前槽的趋势、波动、回撤、反弹、价格效率和成交额结构；
- 当前 5 分钟实体、振幅和上下影线；
- 严格滞后的日频动量、量价、波动、回撤、换手、估值和规模；
- 当时市场与申万一级行业的收益、广度、离散度和相对强弱；
- 同一交易日、同一信号槽内的横截面分位。

算法、特征和限制见 [WP_V3_MODEL_CARD.md](docs/WP_V3_MODEL_CARD.md)，三年
验证方法见 [WP_V3_BACKTEST_PROTOCOL.md](docs/WP_V3_BACKTEST_PROTOCOL.md)。
文件路径保留 `v3` 名称是为了兼容既有 Pages、账本和自动化接口，不表示仍在
运行旧模型。

## 三条链路

1. `Run WP V9 Tail Session`：13:40 启动持续进程，14:00-14:15 暖机，
   14:20-14:50 每 5 分钟形成目标槽并延后 2 分钟读取完整 K 线推理，
   逐槽结算上一信号的参考成交价，
   14:55 结算 14:50 候选并冻结，15:00 清场。
2. `Validate WP Close`：15:08-16:10 获取到期 T+1 收盘真值并逐票结算。
3. `Research WP V9 Hurdle Full Three-Year OOS Model`：构建约五年 point-in-time
   因果面板，最后连续三年作为正式样本外审计，并登记研究、影子观察或影子模型。
   150 日前瞻证据绑定精确 `model_fingerprint`；任何重训模型都从第 0 日重新累计。

上游仓库只用于归档，不阻塞 WP 的实时推理。
